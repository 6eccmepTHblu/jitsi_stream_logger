# Jitsi Stream Logger

Трей-приложение для Windows 11: ждёт, когда в Chrome начнётся созвон Jitsi Meet
на разрешённом домене (по умолчанию `meet.jit.si`), и автоматически:

- журналирует **начало, конец, длительность** созвона и **участников**
  (в `meta.json` в отдельной папке созвона);
- записывает **видео окна** с созвоном (Windows Graphics Capture → FFmpeg);
- записывает **звук обеих сторон**: микрофон + системный звук (WASAPI loopback);
- собирает файлы, готовые к **транскрибации** (16 кГц mono WAV + раздельные дорожки).

## Как это устроено

```
Chrome + расширение (по умолчанию только meet.jit.si)
  page-hook.js — читает состояние Jitsi (APP.*): вход/выход, участники, мьют
      │ WebSocket → 127.0.0.1:8765
Трей-приложение (Python)
  ├─ журнал: meta.json в папке созвона
  ├─ звук: mic_NN.pcm + speakers_NN.pcm  (PyAudioWPatch, WASAPI)
  ├─ видео: video_NN.mkv                 (windows-capture + ffmpeg)
  └─ финализация: call.mp4, mic.ogg, speakers.ogg, mix.ogg
```

## Требования

- Windows 11, Google Chrome;
- Python 3.12 (х64);
- FFmpeg в `PATH` (например, `winget install Gyan.FFmpeg`) — нужен и `ffprobe`;
- Разрешение Windows на доступ приложений к микрофону
  (Параметры → Конфиденциальность → Микрофон → «Разрешить классическим приложениям»).

## Установка

1. **Зависимости** (из папки проекта):

   ```powershell
   py -3.12 -m venv .venv
   .venv\Scripts\python -m pip install pystray Pillow websockets PyAudioWPatch windows-capture pywin32 winotify psutil
   ```

2. **Манифест расширения** (домены берутся из конфигурации):

   ```powershell
   .venv\Scripts\python tools\make_manifest.py
   ```

   `extension\manifest.json` в репозитории не хранится — он генерируется из
   `extension\manifest.template.json`, подставляя `allowed_domains` из
   `config.toml` в оба массива `matches`. Перегенерируйте его после любой
   правки списка доменов и обновите расширение в Chrome.

3. **Расширение Chrome** (один раз):
   - откройте `chrome://extensions`;
   - включите переключатель **«Режим разработчика»** (справа сверху);
   - нажмите **«Загрузить распакованное расширение»** и укажите папку `extension\` этого проекта.
   - после обновления проекта нажмите **«Обновить»** на карточке расширения:
     его закреплённый ID должен быть `indgmclalpjobnolmodgimkjfbkiopcl`.
     Поле `key` в manifest содержит только публичный ключ для стабильного ID;
     закрытого ключа в репозитории нет.

4. **Первый запуск** (с консолью, чтобы видеть лог):

   ```powershell
   .venv\Scripts\python -m app.main --console
   ```

   В трее появится синяя иконка. Зайдите в тестовую комнату на
   `https://meet.jit.si/` — должно прийти уведомление «Запись началась»,
   при выходе (спустя 20 с grace-периода) — «Запись сохранена».

5. **Автозапуск** при входе в Windows:

   ```powershell
   .venv\Scripts\python setup\install_autostart.py
   ```

   (удаление: `--remove`). После настройки приложение запускается без консоли
   через `pythonw`.

6. Для собственного Jitsi-сервера добавьте его домен в `allowed_domains`
   конфигурации, перегенерируйте манифест (`tools\make_manifest.py`) и
   обновите расширение в Chrome. Домен нужен в обоих местах: `allowed_domains`
   решает, какие снапшоты принимает приложение, а `matches` — на какие
   страницы Chrome вообще внедрит content-скрипты.

## Файлы записей

`%USERPROFILE%\Videos\JitsiCalls\<дата_время_комната>\`:

| Файл | Что это |
|---|---|
| `call.mp4` | видео окна созвона + микс звука (или `call.m4a`, если видео не записалось) |
| `mic.ogg` | только ваш микрофон (mono Opus): шумодав, эхо динамиков приглушено, мьют вырезан |
| `speakers.ogg` | только собеседники/системный звук (mono Opus) |
| `mix.ogg` | **единая голосовая дорожка** (компактная — уходит на сервер STT) |
| `transcript.txt` | текст распознавания (если включена транскрипция) |
| `summary.txt` | резюме созвона от LLM (если включено на вкладке «Резюме») |
| `meta.json` | времена, участники, события созвона (журнал записи) |

Отдельной общей БД нет: журнал каждого созвона целиком лежит в его `meta.json`
(секции `call`, `participants`, `events`). Список записей в настройках
формируется разбором папки с записями.

При `auto_record = false` папка всё равно создаётся, но содержит только
`meta.json`: журнал не пропадает, медиафайлы не пишутся. `meta.json`
заменяется атомарно и содержит маркер формата; список и автоочистка игнорируют
чужие подпапки и посторонние файлы с похожими именами.

## Трей и настройки

**Двойной клик по иконке** (или ПКМ → «Настройки…») открывает окно с
вкладками:
- **Настройки** — папка записей, режим видео, обработка звука, транскрипция,
  автозапуск. Изменения подхватываются работающим приложением автоматически
  (в течение ~5 секунд), перезапуск не нужен (кроме смены порта).
- **Качество видео** — две группы радио-кнопок, обе про итоговый `call.mp4`:
  - *Кодек и параметры* — H.264 (по умолчанию, макс. совместимость),
    H.265/HEVC (CRF 30/35), AV1 (CRF 50/55) и VP9 (CRF 40). H.265/AV1/VP9
    дают меньший файл ценой нагрузки на CPU и совместимости. Ключ
    `[video] quality_preset`.
  - *Масштабирование* — «Оригинал» (по умолчанию) либо предел высоты кадра
    1440p / 1080p / 720p / 480p: запись 2K с ограничением 1080p сжимается до
    1920×1080, ширина считается по пропорции, запись меньше предела не
    растягивается. Ключ `[video] scale`. Учтите: с любым масштабом, кроме
    «Оригинала», сборка перестаёт копировать видеопоток как есть и всегда
    пересжимает его — финализация записи идёт заметно дольше.
- **Резюме** — включение резюме, адрес LLM, модель, температура и редактор
  системного промпта.
- **Список записей** — созвоны из папки записей (разбор `meta.json`): двойной
  клик или «Открыть папку» открывает папку записи; «На транскрибацию» ставит запись в очередь
  распознавания; «Резюме» делает резюме по готовому транскрипту (а если его
  ещё нет — предложит сначала распознать). Задачи выполняет основное
  приложение; если оно не запущено — после его старта.

**«Начать запись вручную»** в меню трея — запасной путь, когда расширение
молчит (не загрузилось, домен вне `matches`, Chrome усыпил service worker).
Такая запись не привязана к вкладке Chrome: она не ждёт снапшотов, не следит
за heartbeat и не завершается сама — остановите её тем же пунктом меню
(«Остановить ручную запись»). Видео пишется с экрана: режим *Окно созвона*
для неё подменяется на *Экран, где курсор*, потому что искать окно по
заголовку вкладки в этом случае нечего. Участники и мьюты в журнал не
попадают — их знает только расширение. Когда созвон уже пишется обычным
путём, тот же пункт останавливает его досрочно.

**«Писать только со второго участника»** в меню трея (галочка, сохраняется
в `[general] record_from_second_participant`) — для случая «зашёл раньше всех
и жду». Пока в комнате никого, кроме вас, пишется только журнал; медиа
стартует в момент, когда придёт кто-то ещё, и этот момент становится началом
созвона — получасовое ожидание в пустой комнате не попадёт ни в запись, ни
в длительность. Время захода остаётся в журнале событием `conference_joined`,
а старт записи — событием `record_started` с полем `waited_sec`.

Пока идёт ожидание, иконка в трее зелёная («жду второго участника»), а пункт
записи в меню превращается в **«Начать запись сейчас»** — если ждать надоело
или запись нужна и в одиночку. Если вы ушли, так и не дождавшись, папка
остаётся с одним `meta.json` (статус `log_only` → `done`), без медиафайлов.

Оговорка: режим опирается на список участников от расширения. Если страница
Jitsi сильно изменена и `page-hook.js` свалился в DOM-эвристику, участников
посчитать нечем — тогда запись начинается сразу, чтобы созвон не потерялся
молча (в журнале это видно по `record_started` с `reason: participants_unknown`).

Режимы видео (курсор виден во всех):
- *Окно созвона* — окно Chrome; когда активная вкладка окна не созвон,
  видео на паузе (посторонние вкладки не пишутся);
- *Экран, где курсор* — универсально: пишется монитор, где курсор;
  при переходе курсора запись переключается (~через секунду);
- *Монитор N* — конкретный экран (удобно при демонстрации);
- *Видео отключено* — только звук и журнал.

Цвет точки на иконке показывает состояние: нет точки — ожидание,
🟢 журнал без записи, 🔴 идёт запись, 🟡 ожидание возврата (F5),
🟠 сборка файлов, 🔵 распознавание речи, ⚪ пауза обнаружения.

## Транскрипция (корпоративный сервер STT)

Включается в настройках (или `[transcribe] enabled = true` в конфиге).
После сборки записи `mix.ogg` уходит на `POST {url}/stt/queue-task`,
результат опрашивается по `GET /stt/finished/{task_id}`; текст сохраняется
в `transcript.txt` рядом с записью (путь и событие — в `meta.json`).
Любую прошлую запись можно отправить вручную со вкладки «Список записей».

По умолчанию STT ожидается на `:8090`, LLM — на `:8080` того же хоста
(оба адреса меняются в настройках).

## Резюме созвона (LLM)

Вкладка «Резюме» в настройках: включение, адрес LLM (`/v1/chat/completions`,
vLLM/OpenAI-совместимый), модель, температура и **системный промпт**
(хранится в `%APPDATA%\JitsiStreamLogger\summary_prompt.txt`, кнопка возврата
к стандартному). Цепочка: запись → транскрипция → резюме; транскрипт уходит
в user-сообщение, результат сохраняется в `summary.txt` рядом с записью.
Работает и при ручной отправке из «Списка записей».
При выходе из приложения ожидание результата прерывается; файл можно
отправить вручную:

```powershell
.venv\Scripts\python -m app.transcribe "путь\к\mix.ogg"
```

## Конфигурация

`%APPDATA%\JitsiStreamLogger\config.toml` (создаётся при первом запуске):
домены, папка записей, порт, fps/качество видео, кодек (`h264_nvenc` для NVIDIA),
авточистка старых записей (`[retention] days`), режим «только журнал»
(`auto_record = false`), старт записи со второго участника
(`record_from_second_participant`).
Лог: `%APPDATA%\JitsiStreamLogger\logs\app.log`.

## Ограничения и заметки

- **Предупреждайте участников о записи** — в ряде случаев это требование закона
  и почти всегда — корпоративной этики.
- Свёрнутое окно Chrome → картинка замирает (звук пишется); окно, перекрытое
  другими окнами, пишется нормально. Если активная вкладка окна — не созвон,
  видео на паузе до возврата на вкладку (или включите режим «Монитор N»).
  Захватить фоновую вкладку изолированно средствами ОС нельзя — вкладки
  Chrome не являются отдельными окнами.
- Loopback пишет **весь** системный звук (уведомления мессенджеров и т. п.).
- Мьют микрофона в Jitsi вырезается из `mic.ogg` по событиям мьюта
  (`respect_mic_mute = true`), но «сырой» поток микрофона на диск во время
  записи всё же попадает до финализации.
- Второй одновременный созвон только журналируется (записывается первый).
- Если приложение упало во время созвона, при следующем запуске запись
  автоматически дособерётся из сегментов (`сегменты + segments.json`).
- Обновление Jitsi на сервере может поменять внутренние структуры (`APP.*`) —
  тогда участники перестанут определяться, а вход/выход продолжит работать
  по DOM-эвристике. Это видно в `meta.json` (поле `via: "dom"`).
